두 달 전에 같은 도메인이 같은 경고로 막힌 적이 있습니다. 그때는 오탐이었고, 검토 요청 한 번으로 풀렸습니다. 그 과정은 [① 오탐 편]({% post_url 2026-08-16-google-safe-browsing-false-positive %})에 적었습니다.

이번엔 아니었습니다.

## 같은 경고, 다른 원인

증상은 똑같습니다. 크롬에서 빨간 전체화면, **사기성 페이지(Deceptive pages)** 분류, 투명성 보고서에서도 "이 사이트는 안전하지 않습니다".

여기서 지난번처럼 바로 검토 요청을 넣었다면 그대로 반려됐을 겁니다. **실제로 유해 콘텐츠가 사이트 안에 있었기 때문입니다.**

그래서 순서가 중요합니다.

1. 오탐인지 실제 감염인지 **먼저 판별**
2. 실제 감염이면 **제거가 먼저**
3. 제거를 끝낸 뒤에 검토 요청

판별법은 ①에 적은 것과 같습니다. Search Console이 지목한 문제 URL을 다른 브라우저로 열어보고, 평소 화면이면 오탐, 아니면 실제입니다. 다만 이번 경우처럼 **지목된 URL 자체는 멀쩡한데 원인이 다른 데 있는** 경우도 있습니다. 그래서 URL 하나만 보고 끝내면 안 됩니다.
{: .notice--info}

## 원인을 찾은 방법 — 전 페이지 수집

지목된 URL만 봐서는 답이 안 나와서, 사이트맵에 있는 페이지 전체와 게시판 글을 통째로 수집해서 훑었습니다. 눈으로 클릭해가며 찾는 건 현실적이지 않습니다. 외부 도메인으로 나가는 링크를 전부 뽑아서 정렬하면 이상한 게 바로 튀어나옵니다.

나온 것:

- 도박·카지노·성인 사이트로 나가는 외부 링크가 **특정 게시글 몇 개에 수십 개씩** 몰려 있음
- 위치는 본문이 아니라 **댓글**
- 등록 시점이 **2주 남짓한 기간에 집중** — 사람이 아니라 봇

## 숫자

관리자에서 댓글 목록을 열어보고 규모를 확인했습니다.

| 항목 | 값 |
|---|---|
| 전체 댓글 | 1,162개 |
| 도박·카지노 스팸 | **1,160개** |
| 정상 회원 댓글 | 2개 |
| 집중 등록 기간 | 약 9일 |
| 감염 게시글이 사이트 내에서 링크된 횟수 | 40여 회 |

정상 댓글이 2개였습니다. 2년 동안 회원들이 남긴 게 2개고, 나머지 전부가 봇이었습니다.

## 왜 도메인 전체가 막혔나

게시글 몇 개가 감염된 것뿐인데 사이트 전체가 차단된 데는 이유가 있습니다.

- 감염된 게시글이 홈을 비롯한 여러 페이지에서 **40여 회 링크**되고 있었습니다. 구글 입장에서는 사이트 곳곳이 유해 콘텐츠로 연결되는 구조로 보입니다
- 구글이 지목한 예시 URL은 **로그인 리다이렉트 경로**였습니다. 스팸 댓글이 달린 게시글이 로그인 벽 뒤에 있어서, "로그인시켜서 유해 페이지로 보내는 흐름"으로 분류된 형태였습니다

그래서 감염 게시글 몇 개를 지우는 게 아니라, 스팸을 전량 제거해야 합니다.

## 캡차는 켜져 있었습니다

이 부분이 이번 건에서 제일 중요한 교훈입니다.

해당 게시판에는 **보안문자(캡차)가 켜져 있었고, 빌더가 제공하는 "스팸성 댓글 방지" 옵션도 켜져 있었습니다.** 그 상태로 1,160개가 들어왔습니다.

필터는 통과율을 낮출 뿐 0으로 만들지 못합니다. 특히 비로그인 상태로 댓글을 달 수 있게 열려 있으면, 필터가 무엇이든 시간 문제입니다. 실제로 같은 사이트의 다른 게시판들은 열람 권한이 특정 그룹으로 제한돼 있어서 **한 건도 들어오지 않았습니다.** 차이는 필터 성능이 아니라 **접근이 열려 있었느냐**였습니다.

## 조치 — 3단계

### 1. 스팸 전량 삭제

- 관리자 → **콘텐츠 → 댓글**
- 목록에서 전체 선택 → 댓글 삭제

여기 함정이 하나 있습니다. "모두 선택"이 **현재 페이지에 보이는 20개만** 선택합니다. 1,160개면 이 사이클을 58번 반복해야 합니다.

```
페이지 로드 → 모두 선택 → 삭제 → 확인
```

수작업으로도 못 할 건 아니지만, 이런 건 자동화하는 게 맞습니다. 진행하면서 남은 개수가 1,162 → 1,142 → 1,062 → … → 62 → 2로 줄어드는 걸 카운트로 확인했습니다.

**정상 댓글 2개는 남겼습니다.** 전량 삭제 버튼이 있어도 쓰지 않은 이유는, 그게 회원이 남긴 흔적이기 때문입니다. 2개 때문에 58사이클을 돌린 셈인데, 그럴 만한 값이라고 봅니다.
{: .notice--info}

### 2. 검증

삭제했다고 끝난 게 아닙니다. 감염이 가장 심했던 게시글(이전에 카지노 링크가 27개 잡혔던 글)을 다시 수집해서 **0개**를 확인했습니다. 검토 요청은 이걸 확인한 뒤에 넣습니다.

### 3. 검토 요청

Search Console → 보안 및 수동 조치 → 보안 문제 → **검토 요청**.

설명란에는 **원인과 조치를 구체적으로** 씁니다. ①의 오탐 건과 달리 여기서는 "우리 사이트는 정상입니다"라고 쓰면 안 됩니다. 실제로 유해 콘텐츠가 있었으니까요.

```
커뮤니티 게시판에 봇이 자동 등록한 도박·카지노 스팸 댓글이 원인이었습니다.
해당 스팸 댓글 1,160개를 전량 삭제했고, 정상 회원 댓글만 남아 있습니다.
감염 게시글과 신고된 로그인 리디렉트 URL을 재확인한 결과
더 이상 사기성 링크가 존재하지 않습니다.
재발 방지를 위해 게시판 댓글 기능을 비활성화했습니다.
```

무엇이 원인이었고, 얼마나 지웠고, 재발을 어떻게 막았는지 — 이 세 가지가 들어가면 됩니다.

## 재발 방지 — 댓글 기능을 껐습니다

캡차가 이미 뚫린 상황이라, 필터를 하나 더 붙이는 건 답이 아니라고 봤습니다. **봇이 스팸을 달 자리를 없애는 쪽**을 택했습니다.

- 디자인 모드 → 게시판 위젯 우클릭 → **게시판 설정**
- 하단 옵션의 **댓글 표시**를 **댓글 사용 안함**으로 변경
- 창을 닫으면 게시판 단위로 즉시 서버에 저장됩니다 (별도 게시/배포 불필요)

사이트에 게시판이 **6개** 있었고, 각각이 하위 페이지 곳곳에 흩어져 삽입돼 있었습니다. 게시판 설정 패널의 **연동 게시판 선택** 드롭다운으로 하나씩 불러와 처리한 뒤, 마지막에 연동을 원래 게시판으로 되돌렸습니다.

스팸이 실제로 들어온 건 비로그인 접근이 열려 있던 한 곳뿐이었지만, 나머지도 전부 껐습니다. 지금 안 뚫린 게 안전하다는 뜻은 아니니까요.

설정을 다시 열어서 "댓글 사용 안함"이 유지되는지 확인하세요. 저장 버튼이 없는 UI는 저장이 됐는지 안 됐는지 알 수가 없습니다. 재오픈이 유일한 검증입니다.
{: .notice--warning}

## 결과

| 단계 | 결과 |
|---|---|
| 스팸 제거 | 1,160개 삭제, 정상 댓글 2개 보존 |
| 재검증 | 감염 게시글 유해 링크 0개 |
| 검토 요청 | 제출 완료 |
| 재발 방지 | 게시판 6개 댓글 기능 전부 OFF |

작업 시작부터 종료까지 **1시간 40분**. 그중 절반이 삭제 반복이었습니다. 구글 경고 자체가 풀리는 데는 재크롤링까지 추가로 1~3일이 걸립니다.

## 남는 이야기

**같은 경고인데 원인이 정반대일 수 있습니다.** 두 달 전엔 우리 잘못이 하나도 없었고, 이번엔 우리 게시판이 도박 사이트 링크 창고였습니다. 증상이 같으니 지난번 해법을 그대로 쓰고 싶어지는데, 그러면 반려되고 시간만 갑니다.

**필터가 켜져 있다는 것과 막히고 있다는 것은 다릅니다.** 캡차를 켜뒀다는 사실이 오히려 확인을 안 하게 만들었습니다. 켜놨으니 되고 있겠지, 라고요. 1,162개 중 2개가 정상이 될 때까지 아무도 안 봤습니다.

**게시판을 만들 때 정하고 가세요.** 비로그인 댓글을 열 것인가. 열 거면 누군가 주기적으로 볼 것인가. 둘 다 아니면 처음부터 닫는 게 맞습니다. 나중에 닫는 것보다 훨씬 쌉니다.
