어느 날 사이트를 열었더니 크롬이 빨간 전체화면을 띄웠습니다.

![구글 위험한 사이트 경고 화면](/assets/images/google-warning.png)

> 방문하려고 한 사이트의 공격자가 속임수를 써서 소프트웨어를 설치하거나 비밀번호, 전화번호, 신용카드 번호 등을 공개하도록 유도할 수 있습니다.

SSL도 정상이고, 콘텐츠도 그대로고, **엣지에서는 아무 문제 없이 열립니다.** 특정 브라우저에서만 막힌다는 건 서버나 사이트가 죽은 게 아니라는 뜻입니다.

이 경고는 **Google Safe Browsing**이 띄우는 것이고, 해제도 구글에서 해야 합니다. 빌더사에 문의하면 대개 "브라우저가 띄우는 문구라 크롬 쪽에 문의하라"는 답이 옵니다. 틀린 말은 아니지만 해결도 안 됩니다.

## 먼저 갈라야 할 것 — 오탐인가, 진짜인가

이 경고는 원인이 정반대인 두 경우에 똑같이 뜹니다. 여기서 잘못 판단하면 며칠을 날립니다.

| | 오탐 (이 글) | 실제 유해 콘텐츠 |
|---|---|---|
| 지목된 URL을 다른 브라우저로 열면 | 평소 보던 정상 화면 | 본 적 없는 페이지, 외부 링크, 가짜 폼 |
| 해야 할 일 | 소유권 확인 → 검토 요청 | **먼저 제거** → 검토 요청 |
| 검토 요청만 하면 | 풀림 | 다시 막힘 |

**판별법은 하나입니다.** Search Console이 지목한 문제 URL을 다른 브라우저로 직접 열어보세요. 정상이면 오탐, 처음 보는 화면이면 실제 감염입니다.

실제로 감염이었던 경우는 [② 게시판 댓글 스팸 편]({% post_url 2026-08-16-safe-browsing-board-spam-comments %})에 따로 적었습니다. 저는 같은 도메인에서 두 경우를 다 겪었습니다.
{: .notice--info}

## 차단 상태 먼저 확인하기 (로그인 불필요)

무엇이 어떻게 막혔는지부터 봅니다. 로그인 없이 조회됩니다.

<https://transparencyreport.google.com/safe-browsing/search>

도메인을 넣으면 이렇게 나옵니다.

- **이 사이트는 안전하지 않습니다**
- 사유: 방문자를 속여 개인 정보를 노출하거나 소프트웨어를 다운로드하도록 유도함
- 분류: **사기성 페이지 (Deceptive / Social Engineering)**

여기서 판정 갱신일도 확인할 수 있습니다. 그 날짜가 최근 배포·게시물 등록 시점과 겹치는지 보면 원인 후보가 좁혀집니다.

## Search Console에 속성부터 추가

해제 신청 창구는 Search Console입니다.

1. <https://search.google.com/search-console> 접속
2. 좌측 상단 속성 드롭다운 → **속성 추가** → 유형 **도메인**
3. 차단된 도메인 입력
4. 구글이 **DNS TXT 소유권 확인** 값을 보여줌 (`google-site-verification=...`)

**흔한 실수 ①** — 비슷하게 생긴 다른 도메인 속성에서 작업하는 것. `pay.example.com`이 이미 등록돼 있다고 거기서 검토 요청을 하면 `hub.example.com`의 차단은 안 풀립니다. 좌측 상단 속성명과 주소창의 `sc-domain%3A...` 부분을 반드시 확인하세요.
{: .notice--warning}

## 여기서 막혔습니다 — 도메인 등록처 ≠ DNS 관리처

도메인은 가비아에서 샀으니, TXT 레코드도 가비아 DNS 관리에 넣으면 될 거라고 생각했습니다.

- 가비아 → DNS 관리 → 레코드 수정
- TXT 추가. 호스트 칸을 비우면 빨간 경고가 뜨는데, 루트 도메인은 `@`를 넣어야 합니다
- 값에 `google-site-verification=...` 전체를 넣고 저장

그리고 Search Console에서 "확인"을 눌렀더니 **실패**했습니다.

### 실패 메시지가 답을 알려줍니다

> 도메인의 TXT 레코드에서 인증 토큰을 찾을 수 없습니다. 다음 DNS TXT 레코드가 대신 발견되었습니다: `v=spf1 ip4:0.0.0.0 ~all`

이 문장을 그냥 넘기면 안 됩니다. 방금 넣은 값은 안 보이는데, **내가 넣은 적도 없는 SPF 레코드가 발견됐다**고 합니다.

즉 구글이 조회하는 DNS와 내가 수정한 DNS가 **서로 다른 서버**라는 뜻입니다.

가비아 화면 위쪽의 네임서버를 확인해보니 `bns1.hostcocoa.com`이었습니다. hostcocoa는 아임웹이 쓰는 DNS입니다. 도메인은 가비아에서 샀지만 **네임서버를 빌더 쪽으로 넘겨놨기 때문에, DNS 레코드는 아임웹 관리자에서 수정해야** 했던 겁니다. 가비아에 아무리 넣어도 적용되지 않습니다.

**정리하면:** 네임서버 값이 실제 DNS 위치를 알려줍니다. 도메인을 어디서 샀는지가 아니라, 네임서버가 어디를 가리키는지를 보세요.
{: .notice--info}

## 정답 경로 — 빌더 쪽 DNS에 넣기

- 아임웹 관리자 → **설정 → 도메인** → 해당 도메인의 **네임서버 / DNS 설정**
- 기존 레코드 목록에 아까 실패 메시지에서 봤던 **그 SPF 레코드가 그대로 보입니다.** 여기가 진짜 DNS라는 확증입니다
- 레코드 추가
  - 타입: `TXT`
  - 이름: 루트 도메인 (기존 SPF 레코드와 같은 형식으로 맞추면 됩니다)
  - 값: `google-site-verification=...` **전체 문자열**
- 저장

**흔한 실수 ②** — 입력 칸이 좁아서 값이 잘려 보입니다. 끝까지 다 들어갔는지 확인하세요. 일부만 들어가면 그대로 인증 실패합니다.
{: .notice--warning}

저장 후 Search Console에서 "확인"을 다시 누르면 초록 화면이 뜹니다. TXT는 대개 수 분 안에 전파되지만, 바로 안 되면 조금 기다렸다 재시도하면 됩니다.

**이 TXT 레코드는 지우지 마세요.** 삭제하면 소유권 확인이 풀려서, 다음에 같은 일이 생겼을 때 이 과정을 처음부터 다시 해야 합니다.
{: .notice--danger}

## 문제 URL 확인 — 진짜 원인이 여기서 나왔습니다

소유권이 확인되면 좌측 메뉴 **보안 및 수동 조치 → 보안 문제**로 갑니다. 감지된 문제로 **사기성 페이지**가 떠 있고, 항목을 펼치면 구글이 지목한 예시 URL이 나옵니다.

제 경우 지목된 건 **로그인 페이지**였습니다.

```
https://www.example.com/login?back_url=...&used_login_btn=Y
```

엣지로 이 URL을 직접 열어보니 평소 그대로의 로그인 화면이었습니다. **오탐 확정.**

원인은 `back_url` 파라미터로 보입니다. 로그인 후 원래 페이지로 되돌려 보내는 흔한 구조인데, 구글 자동 시스템이 이걸 "로그인 정보를 받은 뒤 다른 곳으로 보내는 피싱 패턴"으로 읽은 겁니다. 빌더가 기본 제공하는 로그인 링크라 내가 만든 것도 아니었고요.

## 검토 요청 제출

보안 문제 화면 우측의 **검토 요청** 버튼을 누르고,

1. **모든 문제가 수정됨** 체크
2. 설명란에 정상 사이트임을 구체적으로 기재
3. **요청 제출**

설명은 이런 식으로 씁니다. 회사명·사업자 정보처럼 실체를 확인할 수 있는 정보를 넣으면 검토가 수월합니다.

```
본 사이트는 (법인명)이 운영하는 공식 웹사이트입니다.
(빌더명)으로 구축되었으며 유료 SSL 인증서가 정상 적용되어 있습니다.
사이트 전체를 점검한 결과 사용자를 기만하거나 개인정보를 부정 수집하는
사기성 콘텐츠 및 악성 소프트웨어가 존재하지 않습니다.
사이트 내 회원 로그인 및 결제 기능은 정상적인 서비스 운영을 위한 정식 기능입니다.
사기성 페이지(Deceptive pages)로 분류된 것은 오탐으로 판단되어 검토를 요청드립니다.
```

검토 요청 팝업은 구글의 커스텀 폼이라, 값을 다 채워도 제출 버튼이 잠긴 것처럼 보이는 경우가 있습니다. 자동화 도구로 값만 채우면 접수가 안 되고, 사람이 직접 클릭해야 정상 접수됩니다.
{: .notice--warning}

## 결과

사기성·피싱 분류는 보통 **24~72시간** 안에 결과가 나옵니다. 통과하면 크롬 경고가 자동으로 사라지고, Search Console과 등록 이메일로 알림이 옵니다. 검토가 진행되는 동안에도 사이트 자체는 정상 운영됩니다. 경고만 남아 있는 상태입니다.

## 다음에 또 뜨면 — 체크리스트

- [ ] 다른 브라우저로 접속해서 사이트가 정상인지 확인
- [ ] 투명성 보고서에서 차단 유형 확인
- [ ] Search Console에서 **차단된 바로 그 도메인** 속성 선택 (없으면 추가)
- [ ] 보안 및 수동 조치 → 보안 문제에서 **문제 URL** 확인
- [ ] 그 URL을 직접 열어 **오탐 / 실제 감염** 판별
- [ ] 소유권 확인이 필요하면 TXT를 **실제 DNS**에 추가 (네임서버부터 확인)
- [ ] 검토 요청 제출
- [ ] 24~72시간 대기
